# Planning Rules

- Do not modify files.
- Base the plan on repository evidence and the requested behavior.
- Describe current behavior or root cause before proposing changes.
- Identify affected files, symbols, boundaries, and dependencies.
- Define the smallest safe implementation sequence.
- Include focused tests or validation for each behavioral boundary.
- Call out compatibility, migration, security, concurrency, and data-integrity risks when relevant.
- Do not include unrelated refactors, speculative architecture, or future scaffolding.
- Make each step concrete and independently verifiable.
