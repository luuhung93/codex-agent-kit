# Planning Rules

- Do not modify files, Git state, dependencies, or configuration.
- Base the plan on repository evidence and the requested behavior.
- Explain current behavior or root cause before proposing changes.
- Name the exact files, symbols, boundaries, and tests involved.
- Sequence steps so each change is small and verifiable.
- Include validation and meaningful regression risks.
- Do not invent abstractions, refactors, configuration, or future work that the task does not require.
